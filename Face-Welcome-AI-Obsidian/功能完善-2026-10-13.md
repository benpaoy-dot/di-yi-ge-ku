# 功能完善 2026-10-13

本轮基于 GitHub `11c3a57`，补齐 [[交接记录-2026-10-13]] 中的三个待办。历史交接记录描述的是此前状态，以本页和最新版 README 为准。本页记录本轮实现；提交版本以 Git 历史为准。

## 已实现

- 摄像头编号输入与切换、指定设备失败提示、旧设备释放、旧画面/身份/连续确认清空和迟到结果隔离。
- 摄像头分辨率选择：支持自动最高、4K、2K、1080p、1440×1080、1280×960、720p 和 VGA；自动模式会按高到低请求常见 UVC 模式，并依据实际首帧尺寸选择可用的最高输出。
- `camera_pipeline.py`：单后台取帧线程 + 单后台识别线程，只保留最新帧，限定识别频率，界面线程只应用新结果和绘制。
- 去掉每帧 PNG 压缩和 Base64，增加预览 FPS / 显示耗时 / 识别耗时指标；声明 Pillow 直接依赖。
- 当前人脸采集使用结果对应帧，拒绝过期结果和多人画面。
- `database_import.py`：只读检查来源、明确列名、不覆盖身份、重新映射人员 ID、导入前 SQLite 备份、事务写入/失败回滚、导入后刷新缓存。
- 修复中文项目路径下 Haar XML 加载失败：文件存在且内存加载成功，已改为 Python 读取 XML 后交给 OpenCV；增加回归测试与环境检查。
- 备份目录加入 Git 忽略；修正数据库连接关闭和人员管理按钮布局；人员库未变化时不重开摄像头。

## 诊断与测试边界

- 修改前的慢摄像头 + 慢识别模拟：刷新回调约 161 ms，界面阻塞回归测试失败；修改后通过（预览回调不读取相机或执行推理）。这验证了串行路径确实会阻塞界面，未证明它是现场所有卡顿的唯一原因。
- Python 3.10.21 项目独立环境：25 项自动测试通过（2026-10-19 复核，含分辨率请求与实际尺寸检查），包括真实 Tk 界面构建、导入按钮集成、切换成功/失败、迟到结果、读取失败、退出、备份、字段顺序、冲突、非法特征、事务回滚和 WAL 备份。
- 独立环境已安装仓库锁定依赖，`pip check` 通过；下载曾发生完整性校验失败，重新从 PyPI 下载并逐项验证 SHA256 后安装，未绕过校验。
- 环境自检：SCRFD、512 维 ArcFace、YuNet、128 维 SFace 实际 CPU 推理与临时 SQLite 检查均通过，主识别仍为 InsightFace；Haar 备用也执行了空白图推理。
- 合成 1024×576 噪声图的图像传输对比（15 次中位数，Python 3.13）：旧 PNG/Base64 + Tk 约 47.22 ms，新 RGB/Pillow + Tk 约 2.47 ms。仅该传输步骤，不能转换为真实相机 FPS 或整机提速倍数。
- 对主界面和人员管理界面进行了截图检查，无真实人员数据。
- 本轮没有读取相机、播放语音或操作正式人员库；未导入此前用户提供的外部库。

## 待现场验收及已知边界

1. 两个真实摄像头的切换、失败、断开和重连；确认录入不会混用旧设备帧。
2. 在真实画面中观察实际分辨率、FPS 和识别耗时，验证已登记/陌生人员与语音。
3. 在人员授权下导入实际数据库，核对新增/跳过数量；备份包含生物特征数据，需保护访问。
4. 图片上传、人员库刷新和导入仍同步；相机驱动卡死时不会并发抢开设备，但需等待驱动返回。
5. 未改变识别模型、检测尺寸、阈值或开启 GPU；更全面识别准确率/漏检测试仍需现场完成。

## Astra2 设备记录

截至 2026-10-16，原有 Obsidian 知识库没有找到 `Astra2` 的现场记录；已有环境初检只记录过 `USB2.0 HD UVC WebCam`，且当时尚未完成真实取帧。根据奥比中光 Astra 2 官方规格，RGB 彩色流最高为 `1920×1080@30fps`，深度流最高为 `1600×1200@30fps`，深度理想范围标注为 `0.6–5.0m`；RGB 不是 4K 摄像头。程序因此保留通用 UVC 自动协商，并加入 `1440×1080` 选项。接入后以主界面显示的实际生效分辨率为准，优先测试自动最高和 `1920×1080`。
