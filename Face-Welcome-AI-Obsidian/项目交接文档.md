# Face Welcome AI 项目交接文档

## 1. 项目定位

Face Welcome AI 是一个 Windows 本地桌面迎宾原型：通过摄像头检测人脸，与本地人员库中的样本进行比对；确认身份后，在界面中显示姓名并播报“欢迎 xxx”。

当前目标是验证以下完整流程：

```text
启动软件
→ 打开摄像头
→ 检测人脸
→ 与本地人员样本比对
→ 显示姓名或 UNKNOWN
→ 播报欢迎语
→ 展示识别活动
```

当前版本属于本地预览识别原型，不适合直接用于门禁、考勤、支付授权或其他高影响身份决策。

## 4. 当前已经实现

### 实时识别界面

- 16:9 深色科技感桌面窗口。
- 中央显示摄像头画面。
- 人脸框使用 HUD 风格边角和状态颜色。
- 已识别人员框上显示姓名和匹配度。
- 未登记人员显示“未登记人员 / UNKNOWN”。
- 右侧显示当前身份、员工编号、播报语言、匹配分数和语音状态。
- 底部显示最近识别活动和声波反馈。
- 摄像头断开时显示离线状态，可以重新连接。

### 人员管理

通过“人员管理 / 录入样本”可以：

- 新建人员。
- 修改姓名、员工编号和播报语言。
- 删除人员及其人脸样本。
- 采集当前摄像头中的人脸样本。
- 设置自定义欢迎语，支持 `{name}` 占位符。

### 播报语言

- `中文 · zh-CN`：欢迎姓名。
- `English · en-US`：Welcome, Name。
- `中英双语 · zh-en`：先中文，再英文。
- 使用 Windows `System.Speech` 和默认音频输出设备。
- 播报失败时，界面显示“播报失败 · 检查系统语音”。

### 欢迎提示行为

- 识别到人员并触发播报后，左下角“欢迎 xxx”显示约 3.5 秒。
- 3.5 秒后改为“已识别 · 姓名”。
- 同一个人持续停留在镜头前时只播报一次。
- 人员离开后再次进入，才会重新触发欢迎语和播报。
- 右侧身份面板和人脸框上的姓名会继续显示。

## 5. 当前技术实现

### 检测

- 主路径：InsightFace `buffalo_sc`，使用 SCRFD 检测人脸并由 ArcFace 生成归一化身份特征。
- 备用路径：OpenCV YuNet + SFace，输出五点关键点和 128 维特征。
- 兼容回退：OpenCV Haar Cascade；眼睛模型只在回退路径中作为辅助信号。
- 模型文件：`models/buffalo_sc/`、`models/face_detection_yunet_2023mar.onnx`、`models/face_recognition_sface_2021dec.onnx`。
- 模型通过内存加载，避免项目目录包含中文时 OpenCV 直接读取 ONNX 失败。

### 当前检测参数

| 参数 | 当前值 | 作用 |
|---|---:|---|
| `insightface_match_threshold` | `0.45` | ArcFace 余弦相似度初始门槛，需现场校准 |
| `sface_match_threshold` | `0.363` | SFace 余弦相似度门槛 |
| `legacy_match_threshold` | `0.76` | 无模型时旧灰度特征回退门槛 |
| `identity_confirmation_frames` | `2` | 连续两帧确认身份 |
| `yunet_score_threshold` | `0.75` | YuNet 人脸检测置信度 |
| `yunet_nms_threshold` | `0.30` | YuNet 重叠框抑制 |
| `detection_scale_factor` | `1.12` | Haar 多尺度检测步进 |
| `detection_min_neighbors` | `5` | 候选框稳定性 |
| `detection_min_size` | `55 × 55` | 忽略过远或过小的人脸 |
| `face_aspect_min` | `0.72` | 人脸框宽高比下限 |
| `face_aspect_max` | `1.32` | 人脸框宽高比上限 |
| 欢迎提示时长 | `3.5 秒` | 左下角欢迎语短时显示 |

### 当前身份匹配方式

InsightFace 模型存在时优先使用：

```text
SCRFD 检测人脸和关键点
→ ArcFace 生成归一化特征
→ 与同一人员的多份 InsightFace 样本计算余弦相似度
→ 取最高分并与 0.45 初始门槛比较
→ 连续两帧得到同一人员后确认
```

InsightFace 不可用时自动切换为 YuNet + SFace，再不可用才使用 Haar + legacy。

相关函数：

- `extract_sface_feature()`
- `extract_recognition_feature()`
- `match_face()`
- `detect_faces()`
- `process_frame()`

旧版 48x48 灰度特征保留为模型缺失时的兼容回退；InsightFace 主路径不会与 SFace 或 legacy 样本混用。切换到 ArcFace 后必须重新采集 InsightFace 样本。

## 6. 数据库结构

数据库文件：

```text
face_welcome.db
```

主要数据表：

### `people`

保存人员资料：

- `id`
- `name`
- `employee_id`
- `language`
- `welcome_text`
- `created_at`

### `face_samples`

保存人脸特征样本：

- `id`
- `person_id`
- `feature`
- `feature_type`
- `created_at`

`feature` 是 `float32` 特征向量的二进制内容，不是原始照片。新主路径样本的 `feature_type` 为 `insightface`，备用样本为 `sface`，旧样本为 `legacy`。

当前数据库检查过的情况：

- 人员数量：2。
- 当前数据库检查到 2 名人员、4 份旧版 `legacy` 样本。
- 旧版样本之间差异很大，同一人员样本最低相似度约 0.49，不能通过降低阈值可靠修复。
- 使用 ArcFace 前必须重新采集 InsightFace 样本；旧样本和 SFace 样本不会参与 ArcFace 主路径身份判断。

重要结论：样本数量多不等于样本质量高。错误检测框、模糊帧、光照差异和眼镜变化可能会污染人员库。

## 7. 阈值试验记录

| 阈值 | 现场结果 | 结论 |
|---:|---|---|
| `0.82` | 容易把相似但不属于登记人员的目标识别成已登记人员 | 偏低，不作为默认值 |
| `0.90` | 真实登记人员容易识别不到 | 偏高，不适合当前样本和摄像头 |
| `0.86` | 当前误识别和漏识别之间的折中候选 | 当前基线，仍需现场验证 |
| `0.84` | 后续可作为“识别不到时”的试验值 | 需要配合陌生人误认测试 |
| `0.88` | 后续可作为“误识别时”的保守值 | 可能增加漏识别 |

阈值只对当前摄像头、光线、距离和样本有效，不能直接当作通用安全阈值。

## 8. 当前已知问题

### 样本质量问题

当前采集会从画面中选择面积最大的人脸，并在保存前检查：

- InsightFace 或 YuNet 检测置信度是否至少为 `0.82`。
- 人脸框最小边长是否至少为 `72` 像素。
- 人脸区域清晰度、对比度和亮度是否合格。
- 当前活动识别后端所需的关键点是否完整。
- 是否与同一人员已有样本过于重复（相似度 `>= 0.992`）。

不合格样本会直接提示原因，不会保存；模型可用时也不会把失败样本降级保存为旧版灰度特征。人员管理中的“可用样本”只统计当前识别模型能使用的样本。

### 算法稳定性问题

主路径已经切换到 InsightFace / SCRFD / ArcFace，但仍需现场验证以下场景：

- 戴眼镜和镜片反光。
- 头部轻微转动。
- 摄像头自动曝光和不同光线。
- 人脸距离变化。
- 多人同时出现。

旧版灰度模板仍对裁剪偏移和光照变化敏感，只作为无模型时的兼容回退。

### 多帧状态问题

当前已经实现连续两帧确认，以及“同一个人持续停留只播报一次、离开后再次进入重新播报”的基础状态。后续仍应增加：

- 短暂漏检容错。
- 离开确认延迟。
- 多人同时出现时的身份切换逻辑。

### 识别记录问题

当前底部活动区是内存中的最近活动，不是完整的持久化识别历史。后续应增加 `recognition_events` 表和记录查询页面。

## 9. 交接后建议优先级

### P0：先保证现场可用

- 删除或忽略当前旧版样本。
- 每人重新录入 3-5 份高质量 InsightFace/ArcFace 样本。
- 可在人员管理中使用“从图片上传样本”批量导入本地单人照片，不必到摄像头前现场采集。
- 测试正面、戴眼镜、不同距离和不同光线。
- 测试陌生人是否会被误认。
- 测试播报实际是否能从扬声器听到。

### P1：继续提高采样质量

- 采集前连续确认人脸框稳定。
- 增加“清空该人员样本”按钮。
- 采集完成时记录质量指标和对应样本。

### P2：提高识别可靠性

- 增加离开/重入状态机。
- 增加识别事件持久化。
- 增加模型加载失败和语音设备检测。

### P3：产品化

- 从 Tkinter 迁移到 PySide6/QML。
- 增加设置页和阈值配置。
- 增加数据备份、导出和删除。
- 增加安装包和首次运行引导。
- 核对模型许可证、隐私和部署要求。

## 12. 当前交接结论

当前项目已经完成从“摄像头脚本”到“可操作桌面迎宾原型”的第一阶段验证，界面、人员库、样本采集、匹配显示、欢迎播报和基础状态反馈已经连通。

下一阶段的核心不是继续无限增加样本，而是先清理样本、提高采集质量，再评估更可靠的人脸嵌入模型。任何涉及身份确认的正式用途，都必须在完成误识别、漏识别、活体和隐私评估后再决定。
