# 人脸检测与识别两阶段升级方案

## 背景

当前程序使用 InsightFace / SCRFD 检测人脸，并在同一轮处理中提取 ArcFace 特征、匹配本地人员库。远距离人脸可能因为画面中的脸部像素过少、光线不足、运动模糊或检测尺寸限制而漏检；即使检测到，细节不足时也不应强行判断身份。

本次升级目标是把“发现人脸”和“判断身份”明确拆成两个阶段，在不降低误识保护的前提下，尝试提高小脸候选的发现率。

## 两阶段流程

### 第一阶段：人脸检测

1. 从摄像头最新帧中检测人脸候选框。
2. 候选框先以“未识别”状态显示，不立即绑定姓名。
3. 检测阶段允许保留尺寸较小但仍有可信度的候选，用于观察远距离漏检情况。
4. 检测结果与帧号绑定，不能把旧帧的身份结果套到新帧上。

### 第二阶段：身份识别

1. 对检测到的候选执行尺寸、置信度、清晰度、亮度和关键点检查。
2. 只有通过质量门的候选才提取 ArcFace 特征并与登记样本匹配。
3. 匹配低于现有阈值时保持 `UNKNOWN`，不得显示或播报登记人员姓名。
4. 小脸、模糊脸、遮挡严重或特征不稳定的候选可以继续显示检测框，但身份保持未确认。

## 是否能识别更远的人脸

这个方案**可能提高远处人脸的检测率，但不会自动突破摄像头的物理识别距离**。

它能改善的部分：

- 先检测再识别，避免所有检测候选都直接进入身份匹配。
- 对小脸候选单独统计和处理，便于调整检测阈值而不降低身份匹配阈值。
- 可以评估更高检测输入尺寸或有限多尺度检测，让模型更容易发现小脸。
- 只对通过质量门的人脸识别，减少小脸导致的误识。

它不能解决的部分：

- 镜头没有采集到足够脸部细节时，放大图像不能恢复真实信息。
- 对焦、逆光、噪声、运动模糊、遮挡和摄像头本身分辨率仍然是主要限制。
- 更高输入尺寸或多尺度检测会增加 CPU 占用和识别延迟。

因此，验收时必须分别记录“检测到人脸”和“正确识别身份”，不能只看框的数量判断远距离识别已经改善。

## 实施边界

- 保留 InsightFace / SCRFD + ArcFace 主路径，以及 YuNet / SFace 备用路径。
- 保留当前身份匹配阈值作为默认值，不为了增加距离而直接降低阈值。
- 先尝试有限的高分辨率或多尺度检测；只有延迟可接受才启用。
- 识别成功仍需要现有的连续确认逻辑，未登记人员仍显示 `UNKNOWN`，不播报姓名。
- 人员样本录入继续使用更严格的质量要求，不使用远距离低质量帧作为登记样本。

## 版本保护与数据边界

实施代码修改前先保存带日期的基线版本。当前工作目录没有 Git 元数据，因此使用独立备份作为回退点。

备份范围：

- 程序源码、测试、启动脚本和环境配置脚本。
- README、Obsidian 笔记和模型文件。

不备份到 GitHub 或公开仓库：

- `face_welcome.db`，其中包含人员资料和人脸特征。
- `.venv`、缓存、临时日志和数据库备份目录。

## 验收指标

- 检测候选可以在没有身份结果时单独显示。
- 只有通过质量门的候选才进入身份比对。
- 小脸候选的检测数量、身份确认数量和误识数量可以分别统计。
- 现有人员匹配、陌生人拒识、连续确认、摄像头切换、样本录入和数据库功能不回归。
- 测量当前检测路径和增强路径的单帧耗时、整体延迟和 CPU 负载。
- 在真实摄像头下按近距离、中距离、远距离、不同光线和运动状态记录检测率与正确识别率。
- 没有现场数据前，不宣称识别距离已经增加。
