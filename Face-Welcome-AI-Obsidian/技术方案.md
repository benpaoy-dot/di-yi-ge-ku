# 技术方案
## 当前原型落地
| 层 | 候选 | 职责 |
|---|---|---|
| 摄像头/帧处理 | OpenCV | 摄像头打开、视频帧读取 |
| 人脸检测与身份比对 | InsightFace SCRFD + ArcFace；备用 OpenCV YuNet + SFace；最后回退 Haar + 灰度特征 | 检测、关键点、特征提取和拒识 |
| 桌面界面 | Tkinter | 快速验证窗口、视频叠层、人员管理和状态反馈 |
| 本地数据 | SQLite | 人员元数据、识别事件和设置 |
| 语音 | Windows 本地 TTS | 离线播报起步，后续评估音色与授权 |

当前程序入口是 `face_welcome_app.py`，数据库文件为程序目录下的 `face_welcome.db`。

### 当前识别参数基线
| 参数 | 当前值 | 说明 |
|---|---:|---|
| `insightface_match_threshold` | `0.45` | ArcFace 余弦相似度初始门槛，需现场校准 |
| `sface_match_threshold` | `0.363` | SFace 余弦相似度门槛；低于该值显示 UNKNOWN |
| `legacy_match_threshold` | `0.76` | 无模型时旧版灰度特征回退门槛 |
| `identity_confirmation_frames` | `2` | 连续两帧确认身份 |
| `yunet_score_threshold` | `0.75` | YuNet 人脸检测置信度 |
| `detection_scale_factor` | `1.12` | Haar 检测尺度步进 |
| `detection_min_neighbors` | `5` | 候选框稳定性要求 |
| `detection_min_size` | `55 × 55` | 过滤过小人脸候选 |
| InsightFace 模型 | `models/buffalo_sc` | SCRFD 检测 + ArcFace 特征，优先加载本地模型 |
| 人脸模型 | `face_detection_yunet_2023mar.onnx` | 输出人脸框和五点关键点 |
| 识别模型 | `face_recognition_sface_2021dec.onnx` | 对齐后输出 128 维归一化特征 |
| 框比例过滤 | `0.72 <= 宽高比 <= 1.32` | 排除异常细长或过宽候选 |

参数调整原则：身份阈值负责“像不像已登记的人”，检测过滤负责“是不是像人脸”；两者分开调试。当前配置在减少背景误框的同时，不再用双眼作为硬门槛，降低戴眼镜时的漏检。

### 人员数据结构
- `people`：姓名、员工编号、播报语言、自定义欢迎语。
- `face_samples`：每个人可保存多份本地人脸特征样本。
- 通过界面“人员管理 / 录入样本”维护，不建议直接改 SQLite 文件。

### 当前使用边界
当前预览优先采用 InsightFace / SCRFD / ArcFace，并使用连续两帧确认身份；InsightFace 不可用时自动切换到 YuNet + SFace，两者都不可用时才回退到 Haar + 灰度特征。人员样本保存前会检查检测置信度、人脸尺寸、亮度、对比度、清晰度、关键点完整性和重复度。它仍不等同于成熟的人脸身份认证系统，产品化时还需要活体检测、数据删除、权限控制和现场误识别评估。

## 模块边界
```text
CameraService        摄像头生命周期与帧采集
FacePipeline         检测、对齐、特征提取
IdentityMatcher      阈值判断与未知人员处理
PresenceTracker      多帧确认、离开/重入状态
AnnouncementService  播报队列、去重和冷却
Repository           SQLite 数据访问
MainWindow/QML       页面状态、叠层和用户操作
```
界面线程不执行模型推理；采集、推理、语音异步运行，避免处理延迟累积。

## 识别门控
1. 检测到人脸后再识别。
2. 连续多帧确认稳定身份，避免单帧触发。
3. 分数不足时拒识为未知；用目标摄像头和现场数据校准阈值。
4. 对确认人员应用冷却；离开后重返可按设置再次播报。
5. 多人同时触发时，语音队列设置上限和过期策略。

## 当前原型的真实边界
- 主路径特征是 ArcFace 的归一化向量；备用路径是 SFace 的 128 维归一化向量；旧版 48x48 灰度特征仅作为现代模型缺失时的兼容回退。
- 当前已完成连续两帧确认，但短暂漏检、多人切换和离开延迟仍需继续完善。
- 当前底部活动区是界面内存活动，不等同于已经持久化的识别事件记录。
- 当前眼睛检测是辅助信号，不再作为硬过滤；仍需根据摄像头角度、眼镜类型和现场距离做数据化校准。
- 语音播报通过 Windows `System.Speech`；程序会显式加载程序集、设置默认音频设备和音量，失败时在界面显示“播报失败 · 检查系统语音”。

## 实测与备选
- 实测逆光/侧脸识别、推理延迟、内存占用、中文 TTS 和离线打包。
- 核验模型来源、使用条款和分发限制。
- Windows 产品化可评估 C#/WPF + ONNX Runtime；快速迭代则先用 Python/PySide6。
- Electron/Web 暂不首选，除非明确需要局域网管理端。

当前以 Python 桌面路线做原型验证，硬件与授权核验后再冻结模型和分发方案。
