# 项目概览
## 目标
构建 Windows 桌面软件：摄像头检测到人脸后，与本地人员库比对；对确认身份的人显示姓名并播报“欢迎 xxx”；将结果写入本地记录。软件应有明确的设备、识别和失败状态，不只是视频脚本。

## 核心流程
```text
启动 → 摄像头扫描 → 检测人脸 → 跨多帧确认身份
→ 显示并播报“欢迎 xxx” → 记录识别时间和结果
```
未知人员显示“未登记人员”，不播报已登记人员姓名。识别和语音异步执行，避免界面卡顿。

## 首版页面
1. 实时识别
2. 人员管理（录入、更新、停用）
3. 识别记录
4. 系统设置（摄像头、语音、冷却时间、识别阈值）

## 初版范围
- 单摄像头、单机本地运行。
- 显示已登记、未登记、未检测到、识别中等状态。
- 对同一人员设置播报冷却，避免逐帧重复播报。
- 对摄像头断开、模型加载失败、语音不可用给出明确反馈。
- 普通人脸匹配不能作为门禁或考勤的充分安全认证；活体检测依场景评估。

## 当前已经完成
- Windows 本地桌面窗口和摄像头实时预览。
- 16:9 深色科技感中控台：中央画面、HUD 人脸框、右侧身份信息、底部活动状态和声波反馈。
- SQLite 本地人员数据库，可在程序内新建、保存、删除人员，并录入多份人脸样本。
- 人脸框显示姓名或“未登记人员 / UNKNOWN”，不会把所有人都显示成同一个名字。
- 支持中文、English、中英双语播报，以及 `{name}` 自定义欢迎语占位符。
- 摄像头断开、重新连接、未登记人员和未检测到人脸等状态反馈。
- 当前主路径采用 InsightFace / SCRFD / ArcFace：检测人脸、输出关键点并生成归一化特征；YuNet + SFace 自动备用，无现代模型时才回退到 Haar + 灰度特征。样本保存前会过滤模糊、过暗、过曝、太小和重复样本。

## 当前参数基线
| 参数 | 当前值 | 目的 |
|---|---:|---|
| ArcFace 身份匹配阈值 | `0.45` | 初始值，需用当前摄像头现场校准 |
| 连续确认帧数 | `2` | 连续两帧同一身份后确认 |
| YuNet 检测置信度 | `0.75` | 过滤低置信度人脸框 |
| 采样最小清晰度 | `35` | 拒绝模糊样本 |
| 采样最小人脸边长 | `72 px` | 避免太远的人脸污染样本库 |

如果现场仍然出现陌生人误认，再优先提高 ArcFace 阈值；如果已登记人员识别不到，先确认人员管理中“可用样本”至少有 3 份，再补充不同角度样本，不要把旧 legacy 或 SFace 样本当作 ArcFace 样本使用。

技术选择暂定，见 [[技术方案]]。

## 当前交互规则
- 欢迎语只在确认身份并触发播报后短暂显示约 3.5 秒。
- 同一个人持续停留在摄像头前时只播报一次。
- 人员离开后再次进入画面，才重新触发欢迎语和播报。
- 欢迎提示结束后，左下角显示“已识别 · 姓名”；右侧身份面板和人脸框继续显示姓名。
